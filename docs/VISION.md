# Loophole — 願景與全家桶

這份文件記錄「我們到底在做什麼、為什麼、以及打算長成什麼樣」。
它不是規格（規格看 [SEMANTICS.md](SEMANTICS.md)），也不是開發筆記（那看 [DESIGN.md](DESIGN.md)）。
它是**方向**，寫下來是為了隔一段時間回來還記得初衷，也為了避免重新提出已經否決過的東西。

---

## 這是什麼、為了什麼

**首要目的是好玩。** 具體一點：讓它**看起來很酷、很專業**。

這個東西本身其實很白痴——把一個神燈笑話寫成編譯器，沒有人**需要**它。
但正因為沒必要，**認真把它搞出來才酷**。這是一個有傳統的品味（esolang、demoscene、
手刻作業系統、code golf）——一堆很厲害的作品存在的唯一理由，就是有人把一件沒必要的事做到極致。

所以判斷任何一個點子的標準不是「有沒有用」「傳播力大不大」，而是：
**這樣做，會不會讓它更酷、更像一個認真的東西。** 效率、觸及率那套產品思維在這裡不適用。

誠實的定位（別自我膨脹）：**這是手藝 + 教學品 + 作品集，不是研究。**
它沒有產生新知識，「形式約束和意圖之間有落差」這件事比它老得多。
但它可以是一個做得非常紮實、非常好玩的東西——這個價值本身就夠了，不需要靠別的名義撐。

## 一句話的核心

> 把「這樣就繞過了吧？」從**嘴砲**，變成**機器驗證的、嚴謹的**東西。

神燈笑話的靈魂是：exploit **不是設計者埋的，是誠實的底層語義的必然後果**。
沒有人「決定」兩位元裝不下 4，那是算術。所以這個專案的嚴謹全部落在**語義被釘死**，
而不是規則被藏起來。規則全部攤開，玩法是「用這套公開的規則，你挖得出什麼」。

## 唯一一條硬底線（最重要，別忘）

把它當一門語言來長，**外皮**可以照現代程式語言的套路長——漂亮的錯誤、REPL、
高亮、formatter、工具鏈，全部歡迎。

但**核心不行**。現代語言往「更會表達、更通用」長；Loophole 的靈魂是反過來的——
它的嚴謹來自那台機器**又小又被釘死**。一旦核心變得圖靈完備，「跑一遍就是嚴謹判定」
這個保證就死了（會撞上停機問題），它就從「一個嚴謹的笑話」退化成「一個比 Lua 爛的通用語言」，
笑點消失。

| 方向 | 能不能加 |
| --- | --- |
| 更多操作、更多軸、精靈語言更會表達 | 可以，都還是可判定的 |
| 更漂亮的錯誤、REPL、高亮、formatter、工具鏈 | 可以，這些是外皮 |
| **迴圈、無界遞迴、圖靈完備** | **不行——加了就殺掉靈魂** |

## 成長的形狀：像 Minecraft 版本迭代

語言靠「一版加一個概念」長大，跟 Minecraft 一版加黑曜石、銅、豬一樣。
**Loophole 1.0** 已經有整數、別名、承諾三條軸，加上人的屬性 + 概念（死亡的例子）；
之後每一版加一個概念（可重綁的死亡、愛情關係、更多情緒……）。**changelog 本身就是樂趣。**

這件事能不能一直長，取決於架構——「加第 N 個概念是一次登記，還是一次特例」。
v1.0 的兩層設計就是為了讓它保持「登記」：**世界的組成（人的屬性）是一層可擴充的資料，
概念（死亡）是建在屬性上的定義。** 兩層都是資料，判別器不動，所以加概念不碰引擎。
細節見 [語言規格](spec/loophole-1.0.md) 和 DESIGN.md。

# 全家桶：三個專案

整體對標 C++ 的生態：Loophole 這門語言，`wishc` 這個編譯器（就像 g++）。
繞著它長出一整個生態，分成三個專案。

## 專案一：本體（loophole）

語言、編譯器、和一門認真的語言該有的一切。以下大部分還沒做，是方向。

### 核心（已完成）

- `wishc`：lexer → parser → AST → 規則檢查 → 語義執行 → 不變量／承諾檢查。
- 三條 exploit 軸：整數（下溢）、別名（可重綁定義）、自我指涉（承諾 + 命題邏輯引擎）。
- `--hunt`：窮舉搜尋器，自己去找 exploit，用最小見證正規化。
- `--genie`：精靈是可載入的資料檔，規則、不變量、概念都是資料。
- 人的屬性 + 概念（兩層世界模型）：死亡的例子，`set` / `kill` / `revive`。
- 正式語言規格（白皮書）：[spec/loophole-1.0.md](spec/loophole-1.0.md)。

### 語言工具鏈（讓它像真的語言）

- **漂亮的錯誤訊息**：指到出錯的 token，底下畫 `^^^`，像 rustc 那樣。CP 值最高的專業感。
- **REPL**：互動模式，打一句願望即時吐判決。
- **語法高亮定義**（tree-sitter / TextMate grammar）：一寫，`.wish` 在各編輯器、GitHub 上自動上色。
- **formatter**：`wishc --fmt`，自動排版。
- **linter**：警告「這個承諾永遠不會被實現」這類問題。
- **除錯器 / 時光倒流回放**：一步步看願望執行，暫存器和狀態即時變化，看著 exploit 展開。
  把「合規且拆穿」變成一段能**看**的動畫。
- **精靈 fuzzer / 自動設計助手**：比 `--hunt` 再進一步——變異精靈，回報「這三個最小改動各堵掉一個洞」。
  就是 careful.genie（在死亡世界 2→1）那件事的自動版。學術上叫 mutation testing 用在規格上。

### 嚴謹的延伸（皇冠級，最對得起靈魂）

- **憑證輸出 + 迷你獨立驗證器**：`wishc` 吐出一張機器可查的憑證（執行軌跡 + 不變量計算），
  一個一百行、跟編譯器完全無關的 `wish-verify` 重跑一遍確認它成立。
  意義：連 `wishc` 都不用信，憑證自己會說話。這是「不准嘴砲」的終極形態（LCF 傳統的核心思想）。
- **用 Lean 證一條關於語義的元定理**：**不是**把檢查器做成 Lean（那個否決了），
  是反方向——檢查器保持原樣，把操作語義在 Lean mechanize，然後證一條 `wishc` 本身不能證的
  全稱命題，例如「對任何位寬 w，過路費下溢都存在」或「R1 是 sound 的」。
  這是整包裡智識上最嚴肅、也最貼近數學系背景的一項；如果哪天想往研究走，這是門把。

### 文件（白皮書那一坨）

- **語言規格 / 白皮書**：給實作者的正式規格。`SEMANTICS.md` 已經是雛形，把它做成正式版。
- **《The Loophole Book》**：給**玩家**的書（跟規格不同）。用「精靈的判例集 / exploit 圖鑑」
  的框架寫，有敘事，像 Rust by Example 但更有戲。`docs/guide/` 已經是雛形。
- **版本號 + changelog**：照 Minecraft 版本的邏輯，每版加一個概念，changelog 是賣點。
- **man page**。
- **真實漏洞類別的對照**：每個 exploit 標注它對應哪一類真實 bug
  （「這是 CVE-xxxx 那類整數溢位的玩具版」「這是 WAF 繞過的玩具版」），
  把玩具變成教真實資安概念的入口。

### 套件系統

- **精靈登記所**：精靈是資料檔，天生可以分享。`loophole install evil-genie-2000`。
  一個社群精靈的市集（Minecraft 模組生態）。有人上傳「號稱滴水不漏」的精靈，
  別人下載來 `--hunt` 打臉、或手動找一個 hunt 沒抓到的洞。
  （有線上成分，實際 hosting 可能跟解題站共用基礎設施。）

## 專案二：VSCode 插件

分兩層，差十倍，別混為一談：

- **語法高亮**（強烈建議先做）：幾十行的 grammar，換來「這是一門真語言」的即視感。
  便宜、酷、CP 值爆表。（微軟的 C/C++ extension 就是這類插件，我們完全可以做。）
- **完整 LSP**（自動補全、行內錯誤、hover）：大工程，而且八成是 UI 水管工程。
  只有真的愛做編輯器工具才做。

## 專案三：解題站

對標 CF / AtCoder / picoCTF。這是整個專案的**多人版 / 社交版**，也是最好玩的方向。

它就是「設計一個精靈，看有沒有人找得出漏洞」那個玩法變成產品。而最大的先天優勢是：
**別人做 judge 系統最難的部分（一個正確、決定性的評判引擎），我們免費就有了——那就是 `wishc`。**

- 提交 `.wish` 挑戰精靈、提交 `.genie` 挑戰別人。
- **Exploit 高爾夫**：最短的 exploit 獲勝。跟已經蓋好的最小見證機制完美搭配。
- **名人堂 / exploit 博物館**：收最短、最歪、最漂亮的 exploit，附評註，開放投稿。
- 每個語言版本一組新挑戰（接 Minecraft 版本迭代）。
- 站上的線上編輯器 = 一個 playground（本體編成 WASM，或 server-side 跑）。

依賴：編譯器要能被嵌入（瀏覽器 WASM 或伺服器端）。所以這個排在生態系比較後面，
等本體穩定、能嵌入之後再長。

## 明確排除的東西（別再提）

- **任何 AI / LLM 相關**（自然語言翻譯成願望、LLM 當玩家……）。
  Ray 不喜歡，之後有靈感再另外討論。而且「自然語言 → 願望」在哲學上跟靈魂打架——
  它把費力消滅的嘴砲/歧義又請回來。
- **核心圖靈完備**（迴圈、無界遞迴）。見上面「唯一一條硬底線」。
- **把效率 / 傳播力當目標**。目標是好玩、是酷。

## 暫緩（不是排除，是時機未到）

- **品牌識別**（logo、神燈圖示、配色、吉祥物）：對「看起來專業」這個目的 CP 值其實很高，
  但是之後的事。
- ~~情感 / 屬性的架構重構~~：**已實作**（v1.0 的兩層世界模型，見語言規格與 DESIGN.md）。
  下一步是往上加更多概念（可重綁的死亡、愛情關係、情緒），一版一個。
