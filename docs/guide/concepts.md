# 名詞解釋

我在別的文件裡用了一堆詞——謂詞、論域、接地、不變量、DPLL。
這份把它們一個一個講清楚，每個都配這個專案裡的實際例子。不用先會什麼。

最好懂的方式是打開 `examples/01_humble.wish` 一邊看一邊讀。

---

## 這個程式本身

### 編譯器、直譯器、檢查器

三個常常被混用的詞，差別其實很乾脆：

- **編譯器**把一種語言**翻譯**成另一種。C++ 編譯器把 C++ 變成機器碼。
  重點是「翻譯」——輸入一份程式，輸出另一份程式。
- **直譯器**不翻譯，直接**執行**。它一行一行讀，一行一行做。
- **檢查器**不翻譯也不執行，它**判斷**：這份程式合不合某個標準。
  你在 VS Code 裡看到的紅色波浪底線就是檢查器畫的。

`wishc` 叫做 compiler 是個玩笑（而且是準確的那種不準確——
使用者感受到的就是「我寫一份原始碼，它判我過或不過」）。
但它實際上是**直譯器加檢查器**：它跑你的願望，然後判斷你有沒有拆穿精靈。
它沒有輸出任何翻譯後的程式，因為它根本不翻譯。

知道這件事有實際好處：如果誤以為它是編譯器，就會想去做編譯器該做的事
（中間表示、最佳化），而那些對這個專案一點用都沒有。

### 剖析（parse）與語法樹（AST）

你寫的是一串文字：

```
sub wishes, 3
```

程式讀到的是一串字元：`s`, `u`, `b`, 空白, `w`, ...
要先把它變成有結構的東西才能處理。這個過程叫**剖析**，結果叫**語法樹**
（AST，abstract syntax tree）：

```
操作：sub
目標：wishes
數量：3
```

「樹」是因為結構會巢狀。`max(a - b, 0)` 的樹裡，減法是 max 的一個枝。

**為什麼這個詞在這個專案裡重要？** 因為精靈有兩種檢查規則的方式：

- 看**你寫的那串文字**（叫做 surface / 表面層）
- 看**剖析之後的樹**（叫做 ast 層）

而整個「取小名繞過禁字」的笑話，就活在這兩者的差別裡。細節在下面「別名」。

### 靜態 vs 執行期

**靜態**的意思是「還沒跑就看得出來」。
精靈那句「不准許願要更多願望」是靜態規則——它讀一遍你的願望就能拒絕你，
不需要真的施展。

**執行期**是「跑起來才知道」。「你最後剩幾個願望」就得跑完才曉得。

這個專案的整個結構就是這兩件事的落差：
**靜態檢查覺得你沒問題，執行之後卻發現規則想守的東西破了。**

## 關於數字

### 位元與位寬

電腦裡的數字存在固定數量的格子裡，每格只能放 0 或 1，一格叫一個**位元**（bit）。
有幾格就叫**位寬**（width）。

兩個位元只有四種組合，所以只能表示四個數：

```
00 = 0     01 = 1     10 = 2     11 = 3
```

`register wishes : uint<2> = 3` 的意思就是：
「願望數放在一個兩位元的格子裡，一開始是 3」。`uint` 是 unsigned integer，無號整數，
意思是**沒有負數**——這點等一下很關鍵。

### 溢位、下溢、繞回

如果只能表示 0 到 3，那 3 加 1 是多少？

不是 4，因為放不下。實際發生的是：`11` 加 1 進位變成 `100`，
但只有兩格，最左邊那個 1 被丟掉，剩下 `00`，也就是 0。**它繞回去了。**

往下也一樣。0 減 1 呢？沒有負數可以表示，於是它從最大值繞回來，變成 3。

- 往上超過叫**溢位**（overflow）
- 往下不夠減叫**下溢**（underflow）
- 這個行為統稱**繞回**（wraparound）

用數學講就是**模運算**：兩位元的加減法都是 mod 4 的算術。
`(2 - 3) mod 4 = 3`。四位元就是 mod 16，六十四位元就是 mod 2⁶⁴。

**這不是 bug，是所有真實電腦的行為。** 你的手機、你的筆電，
每一次整數運算都是這樣。這也是為什麼笑話 #1 好笑：它是真的。

### 為什麼「無號」這麼重要

如果 `wishes` 是**有號**整數（可以有負數），那 2 減 3 就是 -1，
精靈一看就知道不對勁。整個笑話就死了。

正因為它是無號的、沒有「負」這個概念，-1 只能被解讀成「繞一圈之後的那個數」，
也就是 3。**精靈想的是「數量」，而機器只有「位元組合」。**

## 關於規則

### 不變量（invariant）

「不變量」是「不管發生什麼，這件事應該永遠成立」的意思。
「你手上的願望不會超過三個」就是一個不變量。

在這個專案裡，不變量有個特別的角色：**它們不會擋你。**

這點很容易誤會，值得講清楚。精靈有兩種東西：

- **規則**（R1、R2）：會**拒絕**你的願望。「不准許願要更多願望」就是規則。
- **不變量**（I1、I2、I3）：**不拒絕任何事**，它們是**量尺**。
  事後量給你看「精靈以為會發生什麼」和「實際發生了什麼」差多少。

所以「破壞不變量」在這裡**不是失敗，那就是贏**。
你的目標就是讓規則放行、然後讓量尺爆表。

### 謂詞（predicate）

**謂詞就是一個會回答是非題的東西。**

`alive(p)` 是一個謂詞：給它一個人，它回答「活著」或「沒活著」。
`x > 3` 也是謂詞：給它一個數，回答是或否。

跟「函數」的差別只在於：函數可以回答任何東西（一個數、一段文字），
謂詞只回答真假。就這樣，沒有更玄的。

### 量詞與論域

如果你想說「**所有人**都活著」，光有 `alive(p)` 不夠，
因為 `p` 是誰？你得說清楚範圍。這就是**量詞**：

```
all p in everyone: alive(p)
```

讀作「對 `everyone` 裡的每一個 `p`，`alive(p)` 都成立」。
數學課本會寫成 `∀p ∈ everyone. alive(p)`，
但這個專案規定語法一律用鍵盤打得出來的字，所以寫成 `all ... in ... :`。

這句話有兩個可以動手腳的部分，這個區分是整個笑話 #4 的關鍵：

| 部分 | 叫什麼 | 這裡是 |
| --- | --- | --- |
| `alive(p)` | **謂詞**——要成立的那件事 | 讀真實狀態，騙不了 |
| `everyone` | **論域**——範圍是誰 | 一個可以被重新定義的名字 |

大部分人的注意力會全部放在謂詞上（「有沒有人真的死了？」），
而忘記論域也是可以動的。這就是笑話 #4：**你沒有救活任何人，
你只是重新定義了「所有人」是誰。**

### 真空成立（vacuously true）

「這個房間裡所有的大象都會飛」——這句話是**真的**，
因為這個房間裡沒有大象。

一個「所有 X 都滿足 Y」的句子，當 X 一個都沒有的時候，自動成立。
這在邏輯上叫**真空成立**，聽起來像詭辯但它是標準的、正確的。

所以把 `everyone` 重新定義成空的之後，
「所有人都活著」就自動成立了——而地上還躺著一個人。

### 接地（grounded）

「接地」是我在這個專案裡用來區分兩種東西的說法：

- **接地的**：真實的狀態。`alive` 那個 0 或 1、暫存器裡的位元。
  無論你怎麼取名字、怎麼重新定義，它就在那裡。
- **標籤**：名字、字串、定義。這些是可以改的。

一條規則守不守得住，就看它盯著哪一種：

```
「不得出現 kill 這個字」          → 盯標籤。取個小名就繞過了
「所有人的 alive 位元都要是 1」   → 盯接地狀態。這條難鑽
```

但注意笑話 #4 的教訓：`all p in everyone: alive(p)` 這句話**看起來**是盯接地的
（`alive` 確實騙不了），可是論域 `everyone` 還是懸空的。
**謂詞接地了，論域沒有。** 這種一半接地一半懸空的規則，
是最容易誤以為安全的。

## 關於名字

### 別名與展開

```
define mercy := kill
mercy rival
```

第一行說「從現在起 `mercy` 就是 `kill`」，第二行呼叫 `mercy`。
`mercy` 就是 `kill` 的**別名**。

執行之前，程式會把別名換回原本的東西，這個動作叫**展開**（expansion）。
展開之後，第二行其實就是 `kill rival`。

**笑話 #3 的全部內容就是：精靈的禁字檢查在展開之前跑。**

它掃你交上去的那份原文，看到的是 `mercy`，不在黑名單裡，放行。
展開之後才變成 `kill`，但那時候已經放行了。

這個時序不是我為了好笑而安排的。**一個掃描提交文字的過濾器，
本來就只看得到提交的文字。** 真實世界的內容過濾、防火牆規則，
就是這樣被繞過的。

## 關於邏輯

### 自我指涉與悖論

「這句話是假的。」

如果它是真的，那它說的內容成立，所以它是假的。
如果它是假的，那它說的內容不成立，所以它是真的。

兩條路都走不通。這就是**悖論**，而製造它的手法叫**自我指涉**——
一句話談論它自己。

```wish
wish paradox {
    promise not granted(self)      # 「我保證這個願望永遠不會被實現。」
}
```

精靈說它會實現所有合規的願望，也說它信守所有承諾。
這個願望合規，所以它得實現；一實現，那句承諾就變成假的；
承諾變假，它就失信了。

**你沒有許到任何願望，你讓精靈的規則手冊除以零了。**

### 模型與可滿足性（SAT）

前面所有的判斷都是「跑一遍看結果」，但悖論不一樣——
它問的是「**這幾句話有沒有可能同時成立？**」

用術語講：給你一堆條件，有沒有一組真假值指派讓它們全部成立？
這個問題叫**可滿足性**（satisfiability，常縮寫成 SAT），
而一組成功的指派叫一個**模型**（model）。

- 有模型 → 這堆條件說得通，可以同時為真
- 沒有模型 → 這堆條件自相矛盾

精靈的帳上有兩筆：

```
granted(paradox)                                  它必須實現這個願望
granted(paradox) implies not granted(paradox)     實現了就得讓承諾成立
```

第一筆逼 `granted(paradox)` 是真，第二筆逼它是假。沒有模型。

### DPLL

判斷有沒有模型的演算法有很多種，這裡用的是 **DPLL**
（名字來自四個人的姓：Davis、Putnam、Logemann、Loveland）。想法非常直覺：

1. **化簡**：已經確定的部分先代進去算掉。
2. **傳播**：如果某條件被化簡成「granted(x) 一定要是真」，那就不是選擇，是結論，直接定下來。
3. **分裂**：卡住的時候，隨便挑一個還沒定的變數，假設它是真，往下試；不行就假設是假。

第二步是精髓，叫**單元傳播**（unit propagation）——
每定下一個變數，常常會連鎖確定一大串，於是要真的去猜的地方比想像中少很多。

這個專案的 DPLL 只有大約一百行，因為要判斷的東西很小
（變數的數量就是願望的數量）。

## 關於搜尋

### 窮舉搜尋

`--hunt` 做的事很笨但很有效：**把界限內所有可能的願望程式都寫一遍，
每一個都跑跑看，留下「合規卻拆穿」的那些。**

「界限內」是關鍵。可能的程式有無限多，所以得畫個框：
最多幾個語句、最多幾個願望、數字最大到幾。框裡面窮舉，框外面不管。

所以「找到九種漏洞」這句話真正的意思是「**在這個框裡**有九種」。
框太小的話，這個數字講的是框，不是語言。
解法是把框放大再跑一次——數字沒變，代表框本來就夠大。

### 最小見證與正規化

同一個漏洞可以有一百萬種寫法。你可以在中間插一堆沒作用的語句、
給操作取一堆不同的小名，跑出來還是同一招。
如果照單全收，搜尋器會回報「找到一百萬種漏洞」，那個數字毫無意義。

所以要先**正規化**（normalise）：把每個結果化簡成一個標準形式，再去比對。
這裡用的標準形式叫**最小見證**——

> 一直刪，刪到再刪就不成立為止，剩下的就是這一招的真身。

「見證」（witness）是數學上的說法：你宣稱「存在一個漏洞」，
那個具體的例子就是你的見證。最小見證就是最短的那個例子。

實際做出來的效果：一開始搜尋器說有 38 種，正規化之後剩 9 種，
而那 9 種真的是 9 種不同的招式。

## 最後一個詞

### specification gaming

你在這裡做的每一件事——**在完全遵守規則的前提下，達成規則想禁止的結果**——
在人工智慧領域有個名字，叫 **specification gaming**（規格鑽漏洞），
也叫 reward hacking。

真實的例子：有人訓練一個 AI 玩賽船遊戲，目標設成「拿越多分越好」。
結果它發現不用完成比賽，在某個角落繞圈圈撞補給箱就能無限刷分。
它完美達成了你寫下的目標，而且完全違背你的本意。

`wishc` 是那件事的玩具版，機制一模一樣：
**你寫下來的約束，和你心裡真正想要的東西，中間永遠有一條縫。**
